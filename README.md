# yjs-php

A pure-PHP implementation of the Yjs V1 binary update format and the lib0
primitives it is built on.

No Node, no FFI, no WASM, no codec sidecar. The package requires PHP 8.4 on a
64-bit build and nothing else, which is asserted by the test suite rather than
promised in prose.

> **Status: Phases 0–4 done.** The binary foundation, the V1 wire model, the
> update algebra, and the y-protocols codecs are complete and verified against
> the real yjs, lib0, and y-protocols. What remains lives in the collaboration
> server that consumes this package — see [Roadmap](#roadmap).

## Why it exists

To let a Laravel application run a Yjs collaboration server in PHP, beside
Reverb, without a Node process in the production dependency graph.

The library understands the *structure* of a Yjs update but not the meaning of
the document inside it. That boundary is deliberate: it is enough to validate,
merge, diff, and synchronize updates, and it avoids reimplementing the shared
types, which is where the real complexity and the real divergence risk live.

```bash
composer require hemp/yjs
```

## The primitives

```php
use Hemp\Yjs\Binary\Decoder;
use Hemp\Yjs\Binary\DecodeLimits;
use Hemp\Yjs\Binary\Encoder;

$bytes = (new Encoder)
    ->writeVarUint(4711)
    ->writeVarString('hello 😀')
    ->writeAny(['nested' => [1, 2, 3]])
    ->toBytes();

$decoder = new Decoder($bytes, new DecodeLimits(maxByteLength: 1024 * 1024));

$decoder->readVarUint();   // 4711
$decoder->readVarString(); // 'hello 😀'
$decoder->readAny();       // stdClass { nested: [1, 2, 3] }
$decoder->assertAtEnd();
```

Every primitive is byte-identical to lib0's. That is checked against fixtures
generated by the real lib0 build, in both directions.

### Working with updates

```php
use Hemp\Yjs\Update\Update;
use Hemp\Yjs\Id\StateVector;

$update = Update::decode($bytes)->validate();

$update->stateVector();          // how much of each client's history it carries
$update->merge($another);        // one update covering both
$update->diff($peerStateVector); // only the part that peer is missing
$update->contains($candidate);   // whether it introduces anything new
```

Merge and diff produce the same bytes Yjs does. That is checked by building
randomized multi-client histories, merging and diffing them in PHP, and applying
the results with the real Yjs to compare against its own answers.

One thing worth knowing before relying on it: merging is not the same as
applying updates one after another. Integrating sequentially splits items where
merging does not, and a split that lands inside a surrogate pair replaces it with
U+FFFD — so a merged update can preserve an emoji that sequential application
destroys. Yjs does this too. It is a property of the format, not a choice made
here.

### Speaking the protocol

```php
use Hemp\Yjs\Protocol\Sync\{SyncMessageReader, SyncStep1, SyncStep2, ReadOnlyPolicy, SyncAdmission};
use Hemp\Yjs\Protocol\Awareness\{AwarenessStore, AwarenessUpdate};

foreach (SyncMessageReader::decodeAll($frame) as $message) {
    if ($message instanceof SyncStep1) {
        $reply = $message->answer($resident);   // a SyncStep2 with what they lack
    }
}

// What a read-only session may accept.
ReadOnlyPolicy::admit($message, $resident) === SyncAdmission::IntroducesState;

$presence = new AwarenessStore;
$change = $presence->apply(AwarenessUpdate::decode($bytes), now: $milliseconds);
$presence->expire(now: $milliseconds);          // clients that went quiet
```

The Hocuspocus provider frames — the document address, Auth, Close, SyncStatus —
are not in this package. They are the provider's protocol rather than Yjs's, and
they carry session state that belongs in a server.

### Reading untrusted bytes

`Decoder` is the only part of this library that touches input from the network,
and it is written on the assumption that the input is hostile. Declared lengths
and element counts are validated against `DecodeLimits` — and against the bytes
that actually remain — before anything is allocated, so a header claiming a two
gigabyte string costs a comparison rather than memory.

Every failure is a typed `Hemp\Yjs\Exception\DecodeException`. Nothing warns, returns
`false`, or escapes as a `TypeError`; the fuzz suite asserts this over random,
truncated, and mutated input.

```php
use Hemp\Yjs\Exception\DecodeException;

try {
    $update = (new Decoder($fromTheSocket))->readAny();
} catch (DecodeException $failure) {
    // Bounded. Close the connection and move on.
}
```

### UTF-16, which is not optional

Yjs addresses string content in UTF-16 code units because that is what
JavaScript counts. PHP counts UTF-8 bytes. The two agree only below U+0080.

```php
use Hemp\Yjs\Binary\Utf16;

Utf16::length('😀');       // 2 — one surrogate pair
strlen('😀');              // 4 — UTF-8 bytes
Utf16::slice('a😀b', 0, 3); // 'a😀'
```

A clock counts UTF-16 units, so a split of string content can land between the
halves of a surrogate pair. `Utf16::split()` handles that the way Yjs does —
U+FFFD on both sides:

```php
Utf16::split('a😀b', 1);  // ['a', '😀b']  — clean
Utf16::split('a😀b', 2);  // ['a�', '�b']  — pair damaged, lengths intact
```

The character is destroyed, which looks worse than refusing until you count:
a high surrogate is one UTF-16 unit and so is U+FFFD, so each half keeps exactly
the length the surrounding clocks assume. Refusing or widening the split would
change those lengths and invalidate every clock after it.

`Utf16::slice()` is the stricter general primitive and throws at such a
boundary, so reaching for the wrong one fails loudly instead of quietly.

### Inspecting a decoded value

`json_encode` renders `5` for both an int and a whole float, `null` for both
null and undefined, and `{}` for both an empty object and an empty map — which
erases exactly the distinctions worth debugging. `CanonicalJson` keeps them.

```php
use Hemp\Yjs\Debug\CanonicalJson;

CanonicalJson::encode(5);              // 5
CanonicalJson::encode(5.0);            // {"$float":5}
CanonicalJson::encode(-0.0);           // {"$float":"-0"}
CanonicalJson::encode(new stdClass);   // {"$object":[]}
CanonicalJson::encode([]);             // []
```

Two values render identically exactly when they encode to identical bytes, so a
diff of two renderings is a diff of two updates.

## Deliberate differences from lib0

All narrowing; no input a conforming Yjs client can produce is affected. Each is
justified in [`compatibility/profile-1.md`](compatibility/profile-1.md).

- Variable-length integers above `Number.MAX_SAFE_INTEGER`, or wider than 8
  bytes, are rejected rather than returned.
- Invalid UTF-8 in a string is rejected rather than replaced with U+FFFD.
- Declared sizes are bounded before allocation.

PHP also needs help expressing values JavaScript has and it does not.
`Undefined`, `Bytes`, and `BigInt` wrappers keep `undefined` apart from `null`,
a `Uint8Array` apart from a string, and a `bigint` apart from a number. Objects
decode to `stdClass` so that `{}` does not re-encode as `[]`.

## Development

```bash
composer install
composer test                     # pint --test, then the full suite

npm --prefix tools/oracle ci      # only needed to touch the fixtures
composer fixtures                 # regenerate from the pinned lib0
composer fixtures:verify          # lib0 and y-protocols read PHP's output
composer oracle                   # differential test of merge and diff
```

The fixtures in `fixtures/profile-1/` are committed so the suite runs without
Node. Generation is deterministic and carries no timestamp, so regenerating
either produces an empty diff or a real disagreement. CI runs the PHP suite with
no JavaScript installed at all, and separately regenerates the fixtures to prove
the committed bytes are still what lib0 produces.
